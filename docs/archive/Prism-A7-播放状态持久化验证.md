# Prism A7：播放状态持久化验证

## 现状与修改

已有网易播放状态持久化，采用版本 1 的 `playback-state.json`，保留原结构和合成 v0 迁移。继续区分普通歌单与私人 FM 队列；仅保存非敏感曲目元数据，禁止 URL、Cookie、Token 等未知字段。

本轮在独立副本新增 QQ 版本 1 `playback-state-qqmusic.json`，保存有账号归属的 QQ 曲目 MID、可选 mediaMid、顺序与索引、位置、模式、音量和静音；进入工作区的登录恢复先核对账号。新增只含版本号与平台名称的严格 JSON 文件 `playback-state-last.json` 记录最后播放来源，启动按来源恢复但默认暂停，手动播放时才重新请求临时地址；QQ 与网易及 FM 状态分开。所有三个文件使用同目录临时文件、刷新并替换；保存采用 3 秒节流和页面退出时尽力冲刷。状态读取错误不能阻止账号恢复，过期或不匹配的账号状态不会被展示。

最后来源文件和平台状态文件分别原子更新，并非跨文件事务；突然断电或进程强制终止可能留下旧来源标记或最近数秒进度。QQ 会话只在最后来源为 QQ 或用户进入 QQ 工作区时按需恢复。存储文件含非凭据的账号标识及歌名元数据，不是加密数据库。

修改文件：`src-tauri/src/playback_storage.rs`、`src/playback-state.js`、`src/main.jsx`、`src/playback-state.test.mjs`、`src/platforms.test.mjs`、`src/qq-playback-state-integration.test.mjs`、`package.json`。未引入新依赖，也不增加音频实例或后台服务。
