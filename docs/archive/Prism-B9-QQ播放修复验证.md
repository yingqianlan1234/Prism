# Prism B9：QQ 播放 104003 定点排障

## 当前结论

104003 的根因尚未确定。用户在此前独立实测中确认：QQ 交互登录、账号资料、重启恢复以及某个歌单和其曲目列表可见；同一首歌在同一账号的 QQ 官方客户端能完整播放，而 Prism 的普通 `vkey.GetVkeyServer/CgiGetVkey` 返回 104003，未获得播放地址；一次 EVkey 候选同样返回 104003，已撤回。没有真实音频播放、歌词、进度、跨工作区续播或 QQ 队列隔离的真实验证。账号/歌曲未写入本报告。官方客户端可播放不足以证明第三方客户端已获得授权。

## 会话和请求的只读源码核对

- 登录授权窗口只从固定 `https://y.qq.com/` 读取受限的 QQ 账号字段及音乐密钥别名；规范化后，Windows Credential Manager 的 QQ 独立目标仅保存账号和一个密钥。不会读取系统浏览器 Cookie。原 Cookie 的名称、域、路径、到期和刷新信息没有保存；故真实过期、原作用域及是否需要额外字段未知。
- 资料、歌单、播放请求均由本地同一 Credential Manager 目标获取账号和密钥快照，并在异步请求前后检查账号代次；QQ 匿名搜索使用独立、无凭据的 HTTP 客户端，并未直接混入播放。资料接口只检查业务码及昵称，将本地请求账号回填给前端，没有核对响应中的账号字段；因此不能声称服务端身份已与播放账号核对。
- 歌单解析将 `mid/songmid` 作为歌曲标识、`file.media_mid` 作为资源标识；资源标识缺失时回退歌曲 MID。当前请求只构造 `M500<资源标识>.mp3`，实际目标歌曲是否提供对应音质及两个标识是否映射正确尚未验证。URL 仅允许 HTTPS、限定 QQ 音频主机与相对路径；本地十分钟到期是应用保守限制，不是已实测平台有效期。
- [simple-music 源码](https://github.com/Yyyangshenghao/simple-music/blob/37c82b2ec1a877a69b2bd6a792aa23fea2c5351a/server/lib/qq-client.ts)使用同一普通 Vkey RPC，但认证请求形态、Cookie 传递方式、歌曲/资源标识及音质候选与 Prism 不同；`ct=19` 的客户端语义不明，不作为可以冒用的修复。[QQMusicapi](https://github.com/Suxiaoqinx/QQMusicapi/blob/b6d748bb63fc65b6a98a383d8974fe3f3fd75d5b/src/modules/song.js)的客户端协议和设备上下文也不同。这些差异均不是已证明根因；未复制 GPL 源码或未明确许可的代码。
- [社区问题讨论](https://github.com/music-assistant/support/issues/6628)中维护者指出 104003 与授权有关，但实际原因可能涉及会话、账号、地区或上游状态；不能将它直接等同无版权、无会员或已过期。

## 已实现的离线诊断

QQ 工作区开发诊断默认关闭，需本人手动开启，仅在进程内记录白名单：阶段、所需账号/密钥字段是否存在、本地会话结构检查与到期时间未知、是否使用登录态、参数结构、业务码、受限 URL 是否获得、账号代次是否匹配、资源 MID 是否存在及是否与歌曲 MID 相同、失败类别；不会返回字段值、歌曲标识、Cookie、密钥或完整地址。关闭清空快照；每次请求使用递增诊断代次防止旧请求覆盖，账号退出使旧结果失效。资料成功不等于播放授权。上游身份及过期信息没有证据时为“未知”。

代码：`src-tauri/src/qq_web_auth.rs`（内存诊断、固定用途命令、受限播放流），`src-tauri/src/main.rs`（命令注册），`src/main.jsx`（诊断开关及白名单显示），`src/qq-login.test.mjs`（合成 UI）。诊断不引入定时器、常驻服务、第二音频或凭据日志。
