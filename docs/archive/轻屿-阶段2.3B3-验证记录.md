# 轻屿阶段 2.3 B3：QQ 社区扫码登录方案与离线验证

## 调研与证据

[Suxiaoqinx/QQMusicapi 的登录源码](https://raw.githubusercontent.com/Suxiaoqinx/QQMusicapi/main/src/modules/login.js) 描述 QQ 二维码图片和短期会话的获取，单次轮询并解析待扫描、待确认、拒绝、完成等状态，完成后执行授权交换；其文档注明不同平台、设备信息和签名相关实现。源码还列出 music key、访问/刷新凭据及到期字段等模型，具体有效期和本机可用性尚未验证。仅研究接口事实，未移植其代码。

[simple-music 的 QQ 接口说明](https://github.com/Yyyangshenghao/simple-music/blob/master/docs/qq-music-api.md) 描述另一种方式：在官方登录页面由用户扫码，捕获会话；其账号资料候选 `fcg_get_profile_homepage.fcg`，还区分网页会话与播放票据。该项目自身文档称此前有账号只读验证，这不是轻屿的实测。其 [LICENSE](https://raw.githubusercontent.com/Yyyangshenghao/simple-music/master/LICENSE) 为 GPL-3.0；未复制其代码。本次检查 QQMusicapi 主页未见明确许可证标识，常见 LICENSE 路径未取到，具体许可未确认，不复制其实现。

## 拟议数据流（尚未接入）

1. 用户主动启动并本人使用 QQ 客户端扫码确认。候选 Rust 流程只向固定 QQ 登录主机请求二维码，并仅在会话存活期间按有限间隔轮询；取消、拒绝、过期及超时均停止。确切频率、有效期和必要域名需在实施前另行确认。
2. 扫码后的临时会话和授权票据仅在 Rust 内存中处理，交换完成后仅在 Windows Credential Manager 的独立目标 `xianyu.qqmusic` / `session` 中保存必要凭据；不通过前端 IPC 或日志传送 Cookie、Token 或二维码登录票据。二维码图片的安全呈现方式仍需设计审查。
3. 启动恢复时只从独立目标读取，调用经授权的最小资料接口验证后向前端返回必要账号资料与状态；失败显示已过期或待确认，不假报登录成功。本机退出删除该目标，不执行远端注销。实际资料端点、票据结构和到期策略仍未验证。
4. 不规避验证码、设备确认或安全校验；签名及设备会话是否必要尚未验证，若需要不受信或绕过风控的做法则停止。非公开接口可能失效、触发风控或违反平台条款。真实扫码须另行说明完整请求与风险，获得单独确认；本轮不会执行。

## 已实现的离线范围

`src-tauri/src/qq_login_offline.rs`：状态转换、恢复和过期语义、错误类型、凭据存储接口与使用已有 keyring 的独立 Windows 目标；凭据类型不实现 Debug 或 Serialize。模块未注册 Tauri 命令，Windows 存储实现未调用，QQ 实际 Provider 的登录能力依旧 unsupported。内存替身测试只使用虚构数据，不代表 Windows 真实读写、账号恢复、扫码或资料接口通过。`src-tauri/src/main.rs` 仅引入该模块。匿名搜索与 Mock 保留。
